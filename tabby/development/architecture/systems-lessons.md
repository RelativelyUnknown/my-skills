# Lessons from systems projects, in Python and where Python stops

Each row is a habit from a well-run C, C++, Rust or Zig project, the workload it solved there, and what it becomes here. Python first; the native column applies only when the project already has native code or a profile has shown Python cannot do it ([architecture.md](../library/native/architecture.md)). Name your workload before adopting a row ([senior-engineering.md](senior-engineering.md), last section): a rule that fixed a database's problem may not be yours.

| Habit (source) | Solved | In Python | Native, when Python cannot |
| --- | --- | --- | --- |
| **Fail the Nth operation** (SQLite's allocator and file-system hooks) | Recovery code that never runs in tests | Put I/O, the clock and allocation-like calls behind a small interface; a fake raises on call N. Run the operation for N = 1, 2, 3 ... until it succeeds, and after every run check the invariant (the file parses, the totals add up, no handle leaked). Then fail every call from N on | Give the core an allocator and an I/O table the caller can replace; test builds install a failing one |
| **Test through the public surface** (DuckDB's SQL test files, SQLite's TH3) | Tests that break on every refactor | Cases as data (input file, expected output) run by one small driver; assert on results, not on private calls. A refactor then changes no test | The same case files run against the native and the Python reference |
| **A second implementation as the oracle** (SQLite against other SQL engines) | Bugs both the code and its tests share | Compare against the stdlib, a slow obvious version or another library on the same inputs; see differential tests in [rigor.md](../testing/rigor.md) | Keep the Python original as the reference ([porting.md](../library/native/porting.md)) |
| **A narrow, versioned boundary** (curl's frozen public API; DuckDB's unstable C++ internals behind a stable C and Arrow surface; Ghostty's opaque handles) | Callers that break on every internal change | Public names in `__all__`, everything else underscored; the native module is private (`_core`); extend with keyword-only parameters, not new positional ones ([api-design.md](../library/shared/api-design.md)) | Opaque handles with getters and setters keyed by an enum, not one function per field; sized structs and reserved padding; symbol versioning; an ABI diff in CI ([zig.md](../library/native/zig.md)) |
| **Fit the machine** (DuckDB's batches of about 2,000 values; Seastar's core-per-shard layout) | Per-item overhead that dominates | Process a chunk at a time, in columns (NumPy, Arrow, `array`) and not a Python call per row; check for an empty or all-valid case once, not per item. Measure first ([performance](../performance/index.md)) | Only when a profile shows the interpreter's per-item cost is the bottleneck |
| **Shared-nothing** (Seastar, ScyllaDB) | Locks and cache contention between workers | Split work by key; each worker owns its shard outright and receives work through a queue; results come back as values ([concurrency.md](../code/concurrency.md)). Assumes cores you can dedicate | Thread per core with explicit message passing between cores |
| **Know the cost model of the engine you call** (ripgrep and RE2's linear-time matching) | Input that makes a "usual" tool explode | Python's `re` backtracks, so a crafted pattern or input can take exponential time: use a linear-time engine (`google-re2`) for untrusted patterns or input, and a plain `str.find` before a regex for a literal. Say what the fast engine lacks (no backreferences) and keep the fallback explicit, not silent | The Rust `regex` crate behind the same signature |
| **Subtract** (Firecracker's few devices; Hubris's tiny kernel) | Attack surface and code nobody tests | Decline the feature, flag or format nobody asked for; fewer modes is fewer untested paths ([minimalism.md](../code/minimalism.md)) | A smaller core with the rest in the language that checks more |
| **Fix the shape at start-up** (Hubris's build-time task list; TigerBeetle's allocation at start) | Failures that appear only under load | Build pools, caches and routing tables once at start from validated config, with sizes set; after that the hot path allocates no new kinds of resource and cannot be reconfigured | Fixed-capacity structures sized at init; failure at init, not mid-request |
| **Separate privilege, restart the part** (Firecracker's jailer; Hubris restarting a driver task) | One bad component taking down the whole | Run risky work (untrusted files, plugins, converters) in a child process with a timeout, a memory limit (`resource.setrlimit`) and a scrubbed environment; the supervisor restarts it. Never `eval` or `exec` untrusted input ([security-basics.md](../code/security-basics.md)) | seccomp or Landlock filters, namespaces, dropped capabilities |
| **A subset of the language** (LLVM bans exceptions and RTTI; libc++ keeps its own names private) | Features that cost more than they give in one codebase | Ban them in the linter with the reason in config (`ruff` rule selection, `banned-api`), not in prose | `-fno-exceptions`, `-fno-rtti`, `unsafe_code = "forbid"` outside one module |
| **No hidden threads or allocators in a library** (libghostty-vt) | Embedders who cannot control the host | A library starts no thread, no event loop and no connection at import; the caller passes the executor, client or clock | The caller supplies the allocator; the core spawns no threads |
| **Heavy parts load on demand** (DuckDB's extensions; a core with no dependencies) | A big install for a small use | Optional dependency as an extra, imported inside the function that needs it, with an `ImportError` that names the extra ([dependencies.md](../dependencies/dependencies.md)) | A separate loadable module |
| **Check the unsafe seam hardest** (Rust projects run Miri and loom; Android's Rust still has bugs in `unsafe` and FFI) | Trust in a language that stops at the first `unsafe` | Treat every call into native code as input you validate on the way in and check on the way out | Miri for aliasing and uninitialised memory; loom for concurrent `unsafe` ([rust.md](../library/native/rust.md)); sanitizers and a fuzz target for C and C++ |

## Evidence is mixed: verify, do not assume

- Memory-safe languages remove whole classes of bug, not all of them. Mature C projects with heavy fuzzing and static analysis still ship memory bugs; Rust still fails inside `unsafe` and at the foreign-function boundary. A tool or language is a reason to look less often in one place, never a reason to stop looking at the seam.
- Strict limits on function length or assertions per function are one team's calibration. Take the intent (small units that can be checked, invariants stated in code) and keep the project's own numbers.
- Proprietary harnesses (SQLite's TH3 and fuzzer) cannot be copied; their shape can: public-surface cases, injected faults, a reference to compare against, a fuzz pass.
