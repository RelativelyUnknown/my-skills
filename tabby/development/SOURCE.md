## What changed

- Errors: `python-error-handling` (193 + 171 lines) is condensed to three sections: validate and convert to domain types at the edge, exception chaining, batch processing with partial failures. Dropped: the pydantic walkthrough, the exception-hierarchy listing, the status-code mapping, the progress-reporting example. `python-code-style` (360 lines) is a formatter, linter and naming tutorial and is not copied. New, run on Python 3.13: `raise ... from` keeps `__cause__`; `add_note` appears in `__notes__`; `ExceptionGroup` with `except*` handles a batch's failures by type.
- Typing: `python-type-safety` (200 + 237 lines) is condensed to about 20 rules and one examples file. Dropped as conflicting with the no-abstraction-for-one-use and no-`Any` rules: the generic `Result` class and the generic repository; dropped as language-doc restatement: the primer on annotations and unions. Run with `mypy --strict` 2.4.1 on Python 3.13: list invariance and `Sequence`; `TypeIs` requires a subtype of the parameter type; `assert_never` fails on a new enum member; `@override` fails on a typo and `explicit-override` makes it mandatory; `ParamSpec` keeps a keyword-only signature. The `from __future__ import annotations` note and the 3.14 lazy-annotation default (PEP 649, 749) and the pyright strict-mode variant come from documentation and were not run here.
- Resources: upstream body (243 lines) and details (183 lines) are condensed to short rules and one examples file; dropped the protocol-method primer and the logging-based timing block. Run on Python 3.13: `@contextmanager` needs `try`/`finally`; `ExitStack.pop_all`; generators that hold a resource and `contextlib.closing`; `subprocess.run` against `Popen.communicate` timeouts; `ResourceWarning` is silent unless enabled; cancellation runs async cleanup. Examples use stand-in resources so each block runs as written.
- Testing: one section ("Retries and failure sequences") is adapted: a scripted `side_effect` list with three outcomes, rewritten with an injected sleep so the test is instant; the three tests pass under pytest. The rest of `python-testing-patterns` (278 + 761 lines) was already covered in stricter form; the upstream uses freezegun where this repository uses `time-machine`.
- Performance: `python-performance-optimization` (100 + 759 lines) is a profiler tutorial plus an optimization catalogue; `profiling.md` already covers profilers more fully. Folded in, rewritten around measure-first: data structure, doing less work, memory, strings, concurrency. Every ratio was measured on Python 3.13.18 with `timeit` and `tracemalloc`: set against list membership about 500 times, `deque.popleft` against `list.pop(0)` about 200 times, a list against a generator about 40 MB against none, `__slots__` about 1.7 times smaller, `join` against `+=` about 1.8 times. The `lru_cache`-on-a-method instance leak was run. Not run: free-threaded builds (PEP 703, PEP 779) and multiprocessing costs.
- uv: the upstream body (345 lines) and advanced reference (473 lines) are an installation and command tutorial; replaced by decision rules. Run with uv 0.11.32 on Python 3.12/3.13: `uv init --lib` (uv_build backend), `uv add --dev` writes `[dependency-groups]`, `uv sync --locked` fails on a stale lock while `--frozen` installs from it, `uv lock --check`, the `VIRTUAL_ENV` warning, `uv python pin`, `uv export`, `uv tree --outdated`, `uv add --script`, `uv run --with`, `uvx`, workspace members, `--package`, `--no-install-project`. Not run, taken from the uv documentation (`docs/guides/integration/github.md` and `docker.md`, read 7 November 2026): the private-index setting and the CI and Docker examples, including pinned action SHAs and `--no-install-workspace` / `--no-install-package`.
- Packaging: dynamic versioning and console-script entry points are rewritten and rebuilt with uv 0.11.32: hatchling reading `__version__` from a file (0.4.0), hatch-vcs from a tag (1.2.3, then `1.2.4.dev1+g<sha>` one commit later, a local version PyPI rejects), a static `uv_build` version (2.0.0), `[project.scripts]` appearing in `entry_points.txt` and running with `uv run`, and installed metadata staying at the old version until reinstall. `python-project-structure` (252 lines): one concept per file, `__all__`, flat hierarchies and mirrored tests are rules here already; its layered and domain-driven structures are not folded in. Corrected while verifying: with uv 0.11.32 `uv init --package` and `--lib` already write `uv_build`; plain `uv init` writes an application with no build system.
- Design patterns: four short sections: the rule of three, composition over inheritance, passing collaborators in, size by responsibility. Not folded in: KISS and single responsibility as slogans, separation-of-concerns layering, repository and service examples. New, run on Python 3.13: an inheritance example in which overriding `add()` silently changes the parent's `add_all()`, its composition rewrite, and an injected clock.
- Observability: upstream body (229 lines) and details (186 lines) are condensed to about 20 rules and one examples file, rewritten around the standard library first and OpenTelemetry's API/SDK split; structlog, the FastAPI middleware listing and the generic golden-signals tutorial are dropped. Run on Python 3.13 with prometheus-client 0.26.0 and OpenTelemetry 1.45.2 (scratch environment): a context variable reaches log records across `await`, `gather` and `to_thread`; `extra={"message": ...}` raises `KeyError`; lazy log arguments are not formatted when the level is off; Prometheus adds `_total` to counters; OpenTelemetry spans are non-recording before the SDK is configured. Not run: multiprocess mode, the `OTEL_*` variables, `opentelemetry-instrument`, header propagation.
- Configuration: upstream body (215 lines) and details (162 lines) are condensed to about 10 rules and one examples file. The upstream's module-level `settings = Settings()` created at import conflicts with this repository's rules, so the rewrite loads once at the entry point, shows a standard-library loader first and keeps pydantic-settings as the option when the project already uses pydantic. Run with pydantic 2.14.3 and pydantic-settings 2.15.0 (scratch environment): all missing and invalid fields in one `ValidationError`; `"false"` parses to `False`; `SecretStr` stays out of `repr`; constructor values beat the environment; secrets directory reads lower-case prefixed files; source order constructor, environment, dotenv, secrets directory, default. Not run: `env_nested_delimiter`.
- Resilience: upstream body (195 lines) and details (186 lines) are condensed to about 12 rules and one examples file with runnable standard-library retry, breaker and bulkhead using injected time and randomness. Run: retry (Retry-After first, then full jitter, bounded), breaker (closed, open, probe, reset), semaphore bulkhead (peak concurrency 2). With tenacity 9.2.1, httpx 0.28.1, requests 2.34.2: default raises `RetryError`, `reraise=True` raises the original error, `wait_exponential_jitter(initial=...)` emits a DeprecationWarning, httpx default timeout is 5 seconds, `requests` has none. Not run: the status-code list, retry budgets, `Retry-After` date parsing.
- Async: upstream body (295 lines) and details (440 lines) are condensed to about 12 rules and one examples file; the event-loop primer and the scraping, database and WebSocket examples are dropped. Run on Python 3.13: `TaskGroup` failure cancels siblings and raises an `ExceptionGroup`; plain `gather()` leaves the others running; `asyncio.timeout` cancels the body; `Semaphore` caps the peak; `Queue.join` with workers; `to_thread` copies `contextvars`; `aclosing` runs an async generator's `finally`; `asyncio.run` inside a running loop raises `RuntimeError`. Not run: the weak-reference warning for tasks, thread-safety of `Lock`/`Queue`/`Event`, `run_coroutine_threadsafe`.
- Background jobs: upstream body (241 lines) and details (128 lines) are condensed to about 10 rules, a decision section and one runnable standard-library job table (SQLite): atomic claim with `UPDATE ... RETURNING`, idempotency key, expiring leases, retry with backoff and jitter, dead state; run with four worker threads. Celery behaviour (acknowledge before running, `acks_late`, `reject_on_worker_lost`, `retry_backoff`, `retry_jitter`, `autoretry_for`, `max_retries`, `worker_prefetch_multiplier`, one-hour Redis visibility timeout) comes from the Celery documentation (read 7 November 2026) and was not run. The Django `transaction.on_commit` note was not run.
- HTTP services (`apis/http/services.md`, `fastapi.md`, `django.md`, `shared/persistence.md`, `shared/deployment.md`, `apis/shared/security.md`) are original to this repository.
